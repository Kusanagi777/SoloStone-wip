# Handoff: the unified Dungeon Run, phase 8 onwards

For a Claude Code session in a fresh clone of this private repository (Linux container). It has never seen the
Windows PC where phases 1-8 (so far) were built. Read this file first, then `verify/README.md`.

SoloStone is an offline Hearthstone mod: a SabberStone engine fork in `engine/` and a BepInEx plugin in `plugin/`.
The work below folds the five solo adventures into one Dungeon Run mode. Until this export none of it was committed;
the branch `feat/dungeon-run-engine` of this repository holds all of it.

## 1. The goal

Fold all five solo adventures (Dungeon Run, Monster Hunt, Rumble Run, Dalaran Heist, Tombs of Terror) into ONE
Dungeon Run mode, in nine steps:

1. A restoration ledger of every adventure card, hero, power and rule, with its status.
2. Secret-aware AI search and admission checks (which cards the fair AI may meet or play, per side).
3. A shared draft catalog with bucket memberships, randomized offers and dual-class heroes.
4. An escalating act/floor schedule with a saved continuing deck, loadout, rules, progress and mixed encounter
   provenance ("Mix encounter provenance while preserving the mechanics that make each boss distinctive").
5. Persistent deck changes and Bob taverns.
6. 18 heroes, 34 powers, starters, signatures, treasures and evolving artifacts.
7. Shrines and the 54 teammates.
8. "Import all encounter families and global rules. Add original boss decks/powers, special starts, 27 shrines,
   anomaly/twist scripts, and major encounters such as Hagatha, the Heist finale, and phased Plague Lords. Temporary
   hero switching and persistent boss damage need explicit run-owned state."
9. Balance the combined reward economy on one schedule, with act-aware encounter and reward scaling,
   incompatible-modifier prevention, and long-run deck and save/resume validation.

**Done means:** all supported gameplay content from the five adventures is eligible somewhere in this one mode, with
its behaviour and dependencies implemented and tested. Exact campaign sequencing is not required. Every new boss,
power, anomaly or twist needs a script and a regression test that plays it in a real engine game through the run
setup path, with the fair AI piloting the boss (0 faults, 0 fallbacks, 0 swallowed leaf exceptions). It must be
admitted (AI support) or rejected with a stated reason. Do not build a parallel combat engine or a generic plugin
framework: extend the existing run layer, catalog, state, schedule and match plan.

(Step 8 and the completion bar are quoted from `handoff/phase8/workflow-encounters-lanes.js`; the other steps are the
parent session's summary. No file here holds the original nine-step text verbatim.)

These need the Hearthstone client libraries in `references/` (never in git) or the real client, so they cannot run in
the cloud. Note them for the user when a change touches the plugin, the installer or the game.

- The plugin build (the verify suites compile the plugin sources they test, but not the plugin itself):
  `dotnet build plugin/OfflineProbe.csproj -c Debug -p:EngineSource=true -p:Installer=true -p:NuGetAudit=false`
  (wave-3 result: 0 errors, 75 warnings; keep that warning set).
- The launcher tests that need the client: `dotnet run --project installer/SoloStone.Launcher.Tests -c Release`, and
  the full set with skips failing: `sh installer/test-all.sh`.
- Staging: `python3 installer/stage.py --dotnet "$(command -v dotnet)" --out <stage folder outside the checkout> --version <version>`
  (downloads Doorstop, BepInEx and the Mono class libraries: ask first).
- The Mono guard: set `SOLOSTONE_TOOL_DLL="$PWD/installer/out/gate/bin/SoloStone.Launcher.Tests/release/SoloStone.Launcher.Tests.dll"`
  before staging (otherwise "Mono guard skipped"); `installer/mono-assumed.txt` lists APIs still to verify against the
  client's Managed folder.
- Packaging: `powershell -ExecutionPolicy Bypass -File .\installer\build.ps1 -Staged <stage folder> -Version <version> -ClientReference <Hearthstone folder>`,
  ending with `SoloStone.exe check-release`.
- Any check inside the real game client. Nothing of phase 8 has been checked in the client yet.

Details: `docs/BUILDING.md`.
